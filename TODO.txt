---------------------------------------------------------------------
A. RAZORPAY  (dashboard.razorpay.com)
---------------------------------------------------------------------
[ ] 1. Finish business KYC / account activation, so Live mode is enabled.
[ ] 2. Settings > API Keys: generate keys (Test first, Live later). Put in .env:
         RAZORPAY_KEY_ID=rzp_test_...      (rzp_live_... in production)
         RAZORPAY_KEY_SECRET=...
       The app gets the key from the API, so nothing to change in the app.
[ ] 3. Settings > Webhooks > Add webhook (optional but recommended; payments also
       confirm without it because the app polls and the API asks Razorpay):
         URL:     https://chanda.feelathomecare.net/api/v1/webhooks/razorpay
         Secret:  any long random string -> RAZORPAY_WEBHOOK_SECRET in .env
         Events:  payment.captured, qr_code.credited
[ ] 4. Ask Razorpay support to ENABLE ROUTE on the account (needed so online
       contributions go straight to each organiser's bank). Not on by default.
[ ] 5. Ask Razorpay which linked-account "category" / "subcategory" to use for
       puja / community collection committees, and set in .env:
         RAZORPAY_LINKED_CATEGORY=...      (default "others" is a placeholder)
         RAZORPAY_LINKED_SUBCATEGORY=...
       Also confirm "business_type" for organisers (default: individual).
[ ] 6. Ask Razorpay whether QR Codes (UPI QR) are enabled on the account.
       If not, the app still works (goes straight to Checkout), but the QR won't show.
[ ] 7. Decide who pays card / netbanking charges:
       - If the payer should pay: ask Razorpay to enable "Customer Fee Bearer",
         then set RAZORPAY_CUSTOMER_FEE_BEARER=true and RAZORPAY_CARD_FEE_PERCENT
         to the rate on your Razorpay pricing page.
       - If not: leave it false; ChandaBox absorbs card charges (can exceed the ₹2 fee).
       UPI is always ₹0 to the payer (required by law).
[ ] 8. Check the payment capture setting is "Automatic" (the API also captures
       authorized payments itself, so this is just a safety net).
[ ] 9. When steps 4–5 are done: set RAZORPAY_ROUTE_ENABLED=true, then run once
         php artisan payouts:link
       (registers payout accounts saved while Route was off).
       Until then online payment is OFF in the app and members can only pay cash.
[ ] 10. Test end to end in Test mode first (test UPI / test cards), then switch keys to Live.

[ ] 1. .env for production:

                                                      from this; must be reachable by phones)
[ ] 2. php artisan migrate --force
[ ] 3. php artisan storage:link        (profile pictures are served from /storage)
[ ] 4. Cron entry for the scheduler (retries Razorpay transfers every 10 min,
       prunes expired login tokens):

[ ] 5. Queue worker running permanently (QUEUE_CONNECTION=database). Push
       notifications are queued: WITHOUT a worker no push notification is sent.
         php artisan queue:work --tries=3
       Keep it alive with Supervisor (or the host's process manager) and run
       `php artisan queue:restart` after every deploy.
[ ] 6. HTTPS certificate on the domain (Razorpay webhooks and the app need https).
[ ] 7. After changing .env on the server: php artisan config:cache
       (or config:clear if you don't cache config).
[ ] 8. Upload limit: PHP upload_max_filesize / post_max_size >= 6M
       (profile pictures can be up to 5 MB).
[ ] 9. Database backups (contributions and payments are the financial record).
